---
name: Replit Android build environment
description: Workspace-specific storage and JDK constraints for local Android builds.
---

For local Android builds in this workspace, keep the Android SDK/NDK under a workspace `.cache` path and exclude `.cache/` from Git and deployments. Explicitly set both `ANDROID_HOME` and `ANDROID_SDK_ROOT` to that SDK path for Gradle; the SDK can exist while both variables are unset. Use a stable JDK 17, not GraalVM 19; if the Gradle-cached Temurin runtime disappears after a workspace restart, the installed Nix `jdk17` package provides a replacement. Bound Gradle worker count and JVM heaps; React Native CMake compilation across multiple ABIs can exceed the workspace's 8-GiB memory cap. Prefer an arm64 build for a quick current-phone installer, retaining the universal build option.

**Why:** Android SDK/NDK packages can exceed the container's per-user overlay quota even when `df` reports free space, Gradle under the installed GraalVM 19 runtime crashed with SIGBUS during SDK package operations, and parallel C++/Gradle tasks can exhaust the 8-GiB memory limit. On 2026-10-19, Gradle also failed SDK discovery because the environment variables were unset even though the workspace SDK was present. Arm64 release builds can exceed the foreground shell's five-minute limit while CMake is still compiling native dependencies. On 2026-10-21, Nix JDK 17 crashed in `PerfLongVariant::sample()` unless Java perf sampling was disabled; Gradle's default home hit a per-user disk quota, Java/tooling writes under `/tmp` failed despite ample free space, and the managed background-task launcher could not create its log there.

**How to apply:** before building an APK locally, place SDK tools on the workspace volume, select a stable supported JDK, limit Gradle workers/heaps, and keep the generated SDK out of source control and deployment bundles. With Nix JDK 17, set `JAVA_TOOL_OPTIONS=-XX:-UsePerfData`; if the home-directory Gradle cache hits quota, set `GRADLE_USER_HOME=/home/runner/workspace/.cache/gradle`. Set both `TMPDIR` and Java's `java.io.tmpdir` to a writable workspace cache path, since `/tmp` can reject builds and tooling even when `df` shows space. Prefer a monitored background shell for long builds; if its `/tmp` log cannot be created, stage expensive work such as `:app:createBundleReleaseJsAndAssets` separately, then resume the arm64 `:app:packageRelease` build so Gradle can reuse completed tasks between foreground time limits.
