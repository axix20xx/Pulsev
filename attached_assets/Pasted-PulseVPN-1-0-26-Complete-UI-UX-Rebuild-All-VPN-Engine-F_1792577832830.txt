11. Bootstrap DNS and hostname resolution

Inspect configureBootstrapDns() and resolveProxyEndpoint().

Fix the following risks:

* Replacing the configured bootstrap resolver with an unreachable physical DNS server.
* Losing fallback behavior.
* Pinning a hostname to a stale resolved IP after a network change.
* DNS bootstrap loops.
* Hostname endpoints failing even when numeric-IP endpoints work.
* IPv4/IPv6 resolution problems.
* Incorrect handling of Wi-Fi-to-cellular transitions.

Use bounded timeouts, compatible libbox DNS configuration, and safe fallback behavior.

Retain the original hostname and TLS server name separately from a resolved IP where required.

Re-resolve through the current underlying network when reconnecting or recovering from network changes.

Do not disable TLS certificate validation.

Test numeric-IP and hostname-based server configurations independently.
